# OCI Sandboxes

## Introduction

OCI Sandboxes provides managed, isolated Linux environments for running code. Each sandbox has a shell, a filesystem and compute resources that an application or agent can use through APIs. You can run commands, inspect their output and continue working in the same environment across multiple interactions.

Use sandboxes when your application needs to run code supplied by users, generated by models or packaged with agent tools. They separate that execution from the environment hosting your application. Common uses include running code generated by an agent, coding agents that edit and test software, interactive code playgrounds, and temporary web application previews. You can give each user or session its own sandbox without managing a virtual machine for each one.

### Sandbox capabilities

* **On-demand execution and warm pools:** Create environments when work arrives. Warm pools keep idle capacity ready to reduce startup delays.
* **Command and file operations:** Run programs, stream their output, and upload or download files. A Linux shell and filesystem preserve working state across multiple turns within the same running sandbox.
* **Outbound network controls (egress):** Block outbound connections or allow selected domains and ports. Custom networking can route outbound traffic through your own OCI subnet.
* **Published ports (ingress):** Expose a service running in the sandbox through a public HTTPS URL, such as a web application preview. Use OCI IAM for clients that sign their requests, or implement application authentication and authorization for browser users.
* **Session state and snapshots:** Reconnect to a running sandbox by its ID to continue working with its files. Capture filesystem snapshots to create new sandboxes from saved state.
* **Runtime and lifecycle choices:** Choose compute capacity, set an expiration time, and stop or delete environments when work finishes. Custom container images let you supply dependencies for your workload.
* **Access to OCI resources:** Code inside a sandbox can authenticate with its built-in resource principal. IAM policies control which OCI resources it can access and which operations it can perform, such as reading objects or retrieving secrets. You can scope these grants to sandboxes in a specific project. The sandbox also needs network access to the service endpoint: an IAM grant does not override a blocked outbound connection.
* **Sandbox management permissions:** OCI IAM also controls who can create and manage sandboxes through the service APIs.

### What you will build

In this workshop, you will create and use OCI Sandboxes in three ways:

1. **Complete a model response using sandbox execution:** Use OCI Responses API to generate Python code and execute it in a sandbox. Retrieve and inspect the execution results, then send them back to the model so it can process them and return a complete response to the original request. Applications can optionally include code review before execution.
2. **Let an agent carry out the task:** Connect an OpenAI agent to an OCI Sandbox so it can run commands and use their results to complete your request.
3. **Call an OCI service from a sandbox:** Read an object from a private Object Storage bucket using the sandbox's resource principal, without copying user credentials into the sandbox. Grant read access to that bucket through IAM and allow its regional service endpoint on port 443. Compare the request under blocked and permitted outbound access to see why both permissions and connectivity matter.

Lab 2 combines model-generated code with access to Object Storage. Lab 3 uses the same sample analysis with an OpenAI agent. The optional Lab 4 exposes a sandbox application for access from your browser.

### Objectives

* Create a sandbox and inspect its status.
* Transfer files, execute Python, and retrieve the output.
* Generate code, execute it in a sandbox, and return the results to the model for a complete response.
* Connect an agent to a sandbox and inspect its results.
* Choose the outbound access needed for each exercise.
* Combine resource-principal IAM permissions with restricted outbound access to read a private Object Storage object.
